UGC DESIGN SYSTEM --- PROTOTYPE IA

Statut : Design system de prototypage inspiré de l'univers digital public d'UGC.\ Usage : à utiliser comme source de vérité visuelle et UI pour tout prototype généré avec Claude Code.\ Important : ce document n'est pas la charte graphique officielle d'UGC. Les couleurs et dimensions non explicitement publiées par UGC sont des tokens de prototypage cohérents avec l'univers observé sur UGC.fr. Les logos, labels et sélections UGC doivent utiliser les assets officiels lorsqu'ils sont disponibles et ne doivent pas être redessinés ou altérés.

1. INSTRUCTIONS POUR CLAUDE CODE

Pour toute interface créée dans ce projet :

  1. Lire ce fichier avant de générer ou modifier une interface.
  2. Réutiliser les tokens et composants définis ici.
  3. Ne pas inventer une nouvelle direction artistique page par page.
  4. Privilégier les composants existants avant d'en créer de nouveaux.
  5. Conserver une cohérence stricte entre desktop, tablette et mobile.
  6. Faire des affiches de films et visuels cinéma la principale source d'émotion visuelle.
  7. Garder l'interface fonctionnelle, sobre, lisible et orientée réservation.
  8. Respecter l'accessibilité : contraste, navigation clavier, focus visible, labels de formulaires et textes alternatifs.
  9. Ne jamais présenter le prototype comme un service officiel UGC.
  10. Utiliser des contenus fictifs ou autorisés lorsque les droits sur les contenus réels ne sont pas disponibles.

Interdictions visuelles

Ne pas : - utiliser du glassmorphism ; - introduire des gradients violets ou une esthétique générique « AI/SaaS » ; - multiplier les grandes cartes très arrondies ; - utiliser des ombres décoratives fortes partout ; - ajouter des couleurs hors palette sans raison fonctionnelle ; - modifier, étirer, recolorer ou redessiner le logo UGC ; - recréer approximativement les labels UGC lorsqu'un asset officiel existe ; - surcharger les écrans avec des effets graphiques concurrençant les affiches de films.

2. PRINCIPES DE MARQUE

Mots-clés

  • Cinéma
  • Premium
  • Accessible
  • Direct
  • Éditorial
  • Immersif
  • Fonctionnel
  • Réservation
  • Découverte

Principe directeur

Strong cinema imagery + restrained interface.

L'identité visuelle doit principalement provenir : - des affiches de films ; - des photographies cinéma ; - du bleu de marque ; - des labels et sélections ; - d'une typographie forte et lisible.

L'interface sert le contenu. Elle ne doit jamais concurrencer les films.

3.2 Règles couleur

  • --ugc-navy : header, footer, zones premium, fonds institutionnels.
  • --ugc-blue : CTA principaux, liens actifs, sélection.
  • --ugc-electric-blue : accent, focus, interactions ponctuelles.
  • Blanc / gris très clair : surfaces principales.
  • --cinema-black : uniquement pour les expériences immersives, hero cinéma, trailer, événement.
  • Rouge et jaune : accents ponctuels, jamais couleurs dominantes.
  • Ne jamais utiliser la couleur seule pour communiquer un état.

Règles responsive

  • Mobile first.

  • Les carrousels de films peuvent scroller horizontalement sur mobile.
  • Les CTA critiques doivent rester facilement accessibles au pouce.

  • Les modales desktop deviennent de préférence des panneaux plein écran ou bottom sheets adaptés sur mobile.

Règle

8. ICONOGRAPHIE

Pour le prototype, utiliser Lucide Icons ou une librairie d'icônes outline équivalente.

Style : - outline ; - géométrique ; - simple ; - stroke 1.5--2 px ; - cohérent sur toute l'interface.

Icônes de base : - Search - User - MapPin - Heart - Play - Calendar - Clock - Ticket - ChevronDown - ChevronRight - ArrowLeft - Menu - X / Close - Filter - Star - Info - Check - AlertCircle

Ne pas mélanger plusieurs familles d'icônes.

9. LOGO ET ASSETS UGC

Le logo UGC et les éléments de marque officiels doivent être traités comme des assets protégés.

Règles

  • Utiliser uniquement les fichiers officiels lorsqu'ils sont fournis au projet.
  • Respecter leurs proportions.
  • Ne pas modifier les couleurs.
  • Ne pas ajouter d'effet, contour ou ombre.
  • Ne pas recréer le logo en texte.
  • Préserver une zone de respiration autour du logo.
  • Si aucun asset officiel n'est disponible, utiliser un placeholder explicite plutôt que fabriquer un faux logo.

Labels et sélections

Prévoir notamment les catégories observées dans l'écosystème UGC : - UGC Aime - UGC Découvre - UGC Spectateurs - UGC Frissonne - Sélection UGC Family - Sélection UGC Docs - Sélection UGC Culte

Lorsque les assets officiels sont disponibles, ils priment sur tout badge générique.

Dimensions

background: var(--ugc-navy);

États

  • Default : texte blanc.
  • Hover : opacité / soulignement discret.

  • Focus : anneau visible.
  • Mobile : logo + recherche + compte/menu selon espace disponible.

Règles

  • L'affiche est l'élément dominant.

27. ACCESSIBILITÉ

Objectif de prototypage : WCAG 2.2 AA / logique compatible avec les bonnes pratiques RGAA.

Claude doit notamment :

  • utiliser du HTML sémantique ;
  • garantir la navigation clavier ;
  • rendre le focus très visible ;
  • respecter l'ordre logique du focus ;
  • fournir des labels de formulaires ;
  • fournir des textes alternatifs pertinents ;
  • ne pas transmettre une information uniquement par la couleur ;
  • viser un contraste minimum de 4.5:1 pour le texte courant ;
  • viser 3:1 pour les grands textes et composants graphiques lorsque applicable ;
  • utiliser des titres hiérarchisés ;
  • ajouter des noms accessibles aux boutons icônes ;
  • permettre le zoom sans perte de contenu ;
  • respecter prefers-reduced-motion pour les animations.

28. MOTION

--duration-normal: 200ms;
--duration-slow: 300ms;

Utiliser pour : - hover ; - ouverture de menu ; - drawer ; - changement d'état ; - carousel.

Éviter les animations décoratives permanentes.

37. DONNÉES DE PROTOTYPE

Lorsque les données réelles ne sont pas fournies : - utiliser des données mock clairement identifiables ; - ne pas inventer de tarifs réels ; - ne pas inventer de promotions présentées comme actuelles ; - ne pas inventer de caractéristiques d'un cinéma réel ; - ne pas simuler une disponibilité réelle sans l'indiquer.

Pour un prototype interne, les films peuvent être fictifs ou explicitement marqués comme données de démonstration.

38. RÈGLES DE QUALITÉ AVANT LIVRAISON

Avant de considérer un écran terminé, vérifier :

  • [ ] Les tokens du design system sont utilisés.
  • [ ] Aucun style « AI/SaaS » générique n'a été introduit.
  • [ ] Le logo n'a pas été modifié.
  • [ ] Les affiches gardent un ratio cohérent.
  • [ ] La hiérarchie des CTA est claire.
  • [ ] Les états hover/focus/disabled existent.
  • [ ] Le clavier permet d'utiliser les fonctions essentielles.
  • [ ] Les contrastes sont suffisants.
  • [ ] L'écran fonctionne à 320 px de large.
  • [ ] Aucun contenu important n'est tronqué.
  • [ ] Aucun scroll horizontal involontaire.
  • [ ] Les états loading/error/empty sont prévus.
  • [ ] Desktop et mobile utilisent les mêmes principes de marque.
  • [ ] Les composants existants ont été réutilisés avant d'en créer de nouveaux.

39. RÈGLE FINALE POUR CLAUDE

Do not overdesign.

The UGC experience should feel cinematic because of its films, posters, photography and brand identity --- not because of decorative UI effects.

When uncertain: 1. choose the simplest interface; 2. prioritize the movie or cinema content; 3. use UGC blue for the main action; 4. preserve generous whitespace; 5. reuse an existing component; 6. maintain accessibility; 7. keep the booking path obvious.

Consistency is more important than novelty.

40. RÉFÉRENCES DE CONCEPTION

Ce design system de prototypage a été préparé à partir de l'observation des interfaces et contenus publics UGC, notamment : - UGC.fr : navigation Films, Cinémas, recherche, compte, programmation, labels/sélections, news et offres ; - pages UGC Illimité ; - charte UGC publiée par Groupe UGC, qui met à disposition les logos, labels et sélections et précise les règles de protection de la marque.

Les assets officiels UGC doivent être obtenus depuis les ressources officielles et utilisés conformément aux droits et conditions applicables.
